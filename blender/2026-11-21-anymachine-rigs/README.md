## 这是什么

Tripo、Meshy 生成的 3D 模型是一整块：盖子和箱体焊在一起，腿和身体糊成一团，拆开以后铰链不在真正的转轴上，一动就穿模。
AnyMachine 是 apekshik 的一组实验：让 agent（Claude Code）在 Blender 里用 Python **把生成的网格当成一层皮**，从皮上量出关节在哪，把会动的零件重新做成干净的刚体，每个关节一个 0–1 参数，最后用脚本把所有角度扫一遍，证明没有零件互相穿过。

它**不是**一个装上就能用的自动绑骨工具：每个物体都是 agent 新写一份脚本（四足机器人 466 行，步行机约 2,200 行）。作者自己标的状态是 "experiments"，六个实验，没有通用入口。

## 它怎么做到的

从生成网格出发的流程（作者的笔记本、四足机器人、蜘蛛实验）：

| 步 | 做什么 | 作者的例子 |
|---|---|---|
| 1 生成 | 让参考图和模型处于**张开姿态**：盖子开着、膝盖弯着 | 盖子合着就量不出铰链在哪 |
| 2 量关节 | 脚本从网格上量：平面用按面积加权的中位数拟合，盖子方向用 PCA，两者交线就是铰链轴；腿用侧面轮廓找髋和膝 | 用最高点拟合会把桌面坡度量成两倍；左右腿误差 1–7 mm，说明量得可信 |
| 3 留皮、重做运动件 | 保留生成的表面（键盘、外壳），把盖子、腿删掉，按量出的轴重做：盖子后边做成和铰链**同轴**的圆柱，每段腿放在自己的一层板里，留 1–2 mm 间隙 | 生成的盖子比机身短 2.4 cm、和铰链块长在一起 |
| 4 参数化 | 每个关节一个 0–1 自定义属性，烘成一段 1 秒线性动画，引擎里 `seek(参数值)` 就是那个姿态 | glTF 不带驱动器，必须烘焙 |
| 5 机器验收 | 每个参数全程扫：三角面重叠、超范围是否被限住、最小间隙、脚底打滑；导出 GLB 后重新导入核对 | 笔记本 0 重叠、最小间隙 0.32 mm；四足机器人脚滑 0.014 mm |

复杂的静态道具（直升机、救生艇）作者走另一条路：先生成六视图和一批特写参考图，再逐个零件建模，和参考图并排对比，做第二遍补细节。

我的理解（不是作者原话）：关键是**"构造上不可能穿模"优先于"事后修穿模"**。零件和转轴同轴、分层摆放，转到任何角度都碰不上，扫描只是用来证明这一点。

## 为什么值得看

- **补上"生成模型 → 能动的道具"这一步。** 图转 3D 已经很便宜，但出来的东西不能动；常见的自动绑骨（给顶点分蒙皮权重）适合会变形的身体，用在硬壳上会把它弯成橡胶。硬零件绕轴转，这里给了一套做法。
- **验收是数字，不是肉眼。** 一个盖子有上百个开合角度，没人会逐帧看；扫描脚本会告诉你哪一帧、哪两个零件撞上了。
- **作者自己的反直觉结论：** 零件多的复杂道具不要用图转 3D。他们生成的救生艇"轮廓对，下面什么都没有"，被当场否掉。生成网格只适合拿来量关节，或者当没人走近看的背景道具。
- **要注意的地方（看作者材料得出的，不是自己跑的）：** 软体只部分成功，三个背包里两个在控件互相影响的地方失败；重做的运动件很素（"腿就是几块平板"）；仓库里没有任何引擎侧的测试，作者笔记写着直升机 "not yet tested in the game"；`run_all.sh` 写死了作者机器上的路径，不能直接跑。

## 我提炼的工具

[`tools/overlap_check.py`](tools/overlap_check.py)：按作者第 5 步的思路重写的穿模扫描，不依赖他的物体脚本，任何带动画的 `.glb` / `.blend` 都能用。

```bash
blender -b --factory-startup -P tools/overlap_check.py -- prop.glb --all-actions --out report.json
```

- 静止时不挨着的两个零件，之后任何一帧碰上就算不通过（退出码 1）。
- 静止时就挨着的（轮胎压地面、雨刷贴玻璃）只列为"接触变化"，因为转动的零件总会换一批三角面接触；加 `--strict` 也算失败。
- 挂在同一个铰链上一起动的零件（后盖和它的玻璃）直接跳过。

试用结果：一个两控件的测试宝箱，铰链放对时通过；故意把铰链挪进箱体 6 cm 时报错；把盖子的旋转方向写反时也报错。还在一个旧的车辆道具上查出了之前没发现的问题：车开动后，四个轮胎陷进路面约 4 cm。

拿真实的生成模型把整条流程走一遍，后面再补。
