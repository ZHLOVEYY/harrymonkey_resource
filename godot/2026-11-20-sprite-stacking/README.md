## 这是什么

[sprite-stacking](https://github.com/danielwh2/sprite-stacking) 是一个给 AI agent 用的 skill：给它一张
「俯视 / 侧视 / 正视 / 后视」四格像素图，它用算法把这四张剪影求交成一个粗体积，再切成一层层的薄片，
渲染时每片转同样的角度、往上抬一像素 —— 于是**一张平面像素图变成了能转的假 3D 像素雕塑**。

作者 Daniel White（@dwhitedesign）在 2026-11-20 发帖说："I made a skill so your agent can turn anything into
spinning 3D pixel art"，并把方法归功于 @asynkimo 的一篇文章 —— sprite stacking 本身是 indie 游戏里用了很多年的
老技术，这个仓库加的是"四视图雕刻"和"给 agent 用的那套流程"。

## 它怎么做到的

| 机制 | 做什么 | 出处 |
|---|---|---|
| 四视图求交（视觉外壳） | 俯视图定平面轮廓，正/侧视图定高度轮廓，两者相交 = 体素体积。四个方向都看不见的内部空腔会被填实 | `scripts/views_to_slices.py`、SKILL.md 第 1–2 步 |
| 沿高度切片 | 把体积切成 N 层横片，输出成一条横排 PNG（最左是地面片，最右是屋顶片） | 同上 |
| 共享调色板量化 | 四张图先量化到同一套颜色，避免切片之间出现色差接缝 | 同上（`--colours`，默认 24） |
| `--shade` 侧壁阴影 | 给每片的边缘加一点厚度感，不然看起来还是贴纸 | 同上（默认 0.2） |
| 渲染循环 | 每片绕中心转 `turn` → y 压扁 `squash` → 抬高 `spacing` → 最近邻贴图 | SKILL.md 第 3 步、`references/engines.md` |
| 整叠描边一次 | 轮廓在整叠合成之后描一次，不是每片各描一次（每片描边会画出接缝横纹） | SKILL.md 第 3 步 |
| 静态堆栈预烘焙 | 200 棵树 × 30 片 = 每帧 6000 次 draw call，所以静态的要在加载时烘成一张图 | SKILL.md 第 3 步 |

作者给的渲染参数是固定值，不要自己猜：`spacing = 1.0`，`squash = 0.75`（= `sin(相机仰角)`），
旋转中心取对称的 `(w-1) * 0.5` 配 `Math.round` 最近邻采样（用 `floor(... + w/2)` 会在 90°/180°/270°
转向时出现半像素抖动），最后一步才把位置round 到整屏幕像素。

`references/engines.md` 里给了四个引擎各自的配方：Web Canvas / React、Godot 4 的 `Node2D`（约 20 行）、
Unity（每片一个 `SpriteRenderer`）、Phaser / Pygame 等。`scripts/viewer.html` 是一个能单独打开的网页版，
除了转台还有小场景（霓虹街道、草甸小岛）、切片扫描、爆炸图、开车 / 风吹 / 打碎重建的玩法模式、
白天到夜晚的日照、雨水和积雪，以及 16 个朝向的 PNG 雪碧图导出。

## 为什么值得看

- **它省的是美术工时，不是美术能力。** 原来「一件资产能转」= 8 或 16 个方向 × N 帧；现在 = 4 张正交视图。
  而这 4 张图，图像生成模型照着仓库里那份逐字可用的 prompt 就能出。这是把"要多少张图"从指数级压到常数级。
- **真正值钱的不是代码，是那张踩坑表。** SKILL.md 末尾的 Lessons 表有 19 行，每一行都是
  「踩过什么坑 → 变成什么规则 → 由谁强制」。比如"1 像素的杆子转动时会一闪一闪消失 → 至少画 2 像素宽 →
  脚本自动警告"、"俯视图是方的就会雕成一个盒子 → 塔和气球要加 `--round`"。
  把 bug 写成规则、再写成自动检查器，这个做法本身比这个仓库的任何一个函数都更值得抄。
- **它是被写成"给 agent 用的 skill"的。** 作者的用法是"跟你的 agent 说：给我做个能转的像素车"，
  agent 自己去出图、雕刻、渲染。仓库自带一个自检脚本 `tests/check.py`，跑一遍打印 `ok`（我这边跑过了）。
- **一个我自己想到的用法**：拿 3D 项目里已有的模型渲染出四张正交视图，量化成像素再喂进这个切片器，
  等于"把 3D 项目的道具自动变成能转的像素画"。作者没有做这一步。

## 限制

作者自己在 SKILL.md 的 Lessons 表里写明的：

- **空腔会被填实。** 四张剪影都看不见的内部结构（卡车斗、拱洞、杯把中间）挖不出来，只能雕刻后手改切片。
- **鳍片、翅膀、枝叶会雕成方块。** 俯视图必须画真实轮廓，否则这些不规则平面变成矩形。
- **1 像素宽的部件会闪烁。** 旗杆、天线这类要至少 2 像素宽，脚本会警告这种细条。
- **背景被完全包住的区域会雕成实心。** 每条缝隙都得通到视图外面。
- **物体没居中会让旋转偏心。** 底座往一边多伸出一点，整叠就会绕着偏出去的轴转。
- **切片数影响"转起来顺不顺"。** 作者给的档位：粗颗粒复古 15–20 片（约 25×48 px）、细节版 26–44 片、
  视频展示版 36–56 片且只放大 4–6 倍。片数太少又放大太多，转起来会有台阶感。

其他（我自己看仓库 + 看作者材料得出的）：

- **仓库很新。** 2026-11-20 建仓，只有 `main` 分支、没有正式 release，作者还在当天继续提交。
  引用的时候钉一个 commit 比追 `main` 稳。
- **它不是真正的 3D。** 没有真实的背面几何，"看起来像"而已。背面和正面画成一样的物体最安全。
- **不要拿它替代 3D。** 如果你的项目本来就是 3D，用 3D 模型 + 低模 + 着色器做像素化更合适；
  这条管线的价值在"我只有像素画，或者我只有 3D 模型但想要一张能转的像素图"。
